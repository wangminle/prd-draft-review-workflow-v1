# DOCX 资源安全闭环实施计划

**目标：** 修复 Mammoth 回调绕过图片限制，以及转换超时无法终止后台执行的问题。

**架构：** 图片限制在所有图片写入入口统一执行；DOCX 解析迁移到独立工作进程，并采用临时目录转换、成功后发布的事务式流程。

**技术栈：** Python 3、asyncio subprocess、pytest、Mammoth、Pillow/python-docx 测试夹具。

---

### 任务一：建立失败回归测试

**文件：**

- 新增：`tests/test_docx_resource_isolation.py`

1. 构造超过 `MAX_SINGLE_IMAGE_SIZE` 的真实 DOCX 图片并运行完整转换。
2. 断言转换产物中不存在超限资源文件。
3. 构造会在超时后延迟写入的工作进程。
4. 断言超时后进程已退出，且等待后没有延迟产物。
5. 运行测试并确认因当前两个漏洞失败。

### 任务二：封堵 Mammoth 图片回调

**文件：**

- 修改：`skills/docx-to-markdown/scripts/convert_docx.py`

1. 提取统一图片资源校验辅助函数。
2. ZIP 图片提取路径复用辅助函数。
3. Mammoth `convert_image()` 回调在任何写入前复用辅助函数。
4. 运行图片回归测试并确认通过。

### 任务三：引入可终止转换工作进程

**文件：**

- 新增：`src/app/storage/docx_conversion_worker.py`
- 修改：`src/app/storage/review_file_storage.py`

1. 实现工作进程 JSON 输入/输出协议。
2. 将 Skill 转换及必要降级收敛到工作进程。
3. 主进程通过 `asyncio.create_subprocess_exec` 启动并捕获输出。
4. 超时执行 terminate/kill 并等待进程退出。
5. 使用临时目录转换，成功后发布，失败后清理。
6. 运行超时回归测试并确认通过。
