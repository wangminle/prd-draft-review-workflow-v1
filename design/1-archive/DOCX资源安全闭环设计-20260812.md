# DOCX 资源安全闭环设计

## 背景

当前 DOCX 转换仍存在两个可复现漏洞：

1. ZIP 提取阶段跳过的超限图片，会被 Mammoth 的 `convert_image()` 回调再次写入 `assets`。
2. `asyncio.wait_for(asyncio.to_thread(...))` 超时后只能停止等待，无法终止仍在运行的转换线程。

## 方案

### 图片资源限制

在 Mammoth 图片回调读取图片字节后、计算哈希或写文件前，复用与 ZIP 提取阶段一致的限制：

- `MAX_SINGLE_IMAGE_SIZE`：单张图片最大文件大小；
- `MAX_IMAGE_PIXELS`：单张图片最大像素数。

超限图片返回空图片地址，不进入哈希映射，也不写入 `assets`。

### 可终止转换

将不可信 DOCX 的 Skill 转换和 Mammoth 降级转换放入独立 Python 子进程：

1. 主进程创建与正式输出目录同级的临时目录；
2. 子进程仅在临时目录中转换；
3. 主进程按配置等待子进程；
4. 超时后依次执行 `terminate`、限时等待、`kill`，确认进程退出；
5. 失败或超时清理临时目录；
6. 成功后用原子目录替换发布到正式输出目录，并写入源文件哈希。

这样能够保证超时后不会继续消耗资源或延迟写入正式产物。

## 错误处理

- `DocxSecurityError` 在工作进程中转换为明确的安全拒绝退出状态，主进程直接失败，不允许降级。
- 普通 Skill 运行错误保持失败，不把同一不可信文件交给无限制解析器。
- 仅 Skill 模块确实不可用时允许 Mammoth 降级，并同样运行在受超时控制的子进程中。
- 子进程输出使用单行 JSON 协议，业务日志写入标准错误，避免污染结果解析。

## 验证

- 真实构造包含 21MB 图片的 DOCX，完整转换后 `assets` 不存在超限文件。
- 使用测试工作进程模拟延迟写入，超时后确认进程退出且等待后仍无产物。
- 验证 ZIP bomb 安全拒绝不降级。
- 验证正常 DOCX 转换、源哈希缓存和正式目录发布行为不回退。
