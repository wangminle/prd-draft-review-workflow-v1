# Agent 授权与部署依赖缺陷修复设计

## 目标

修复当前未提交变更中确认的 workspace 横向越权、个人 Agent 弹窗误覆盖配置、System Policy 无法清空、DOCX 核心依赖缺失和 Node 锁文件元数据不一致问题。

## 方案

### 授权边界

创建 workspace 类型授权前，后端必须确认目标空间存在且处于 active 状态，并确认当前用户是该空间的 active 成员。RAG 实际执行时再次检查相同条件，防止授权创建后用户被移出空间或空间被归档时旧授权继续生效。不存在、不可见或已失效的空间统一返回 404/403，不依赖前端过滤实现安全。

### 个人 Agent 弹窗

Profile、授权和 workspace 是可编辑配置的必要数据，任一加载失败时弹窗进入错误态并禁止保存。运行记录和审批列表属于辅助数据，可独立显示加载失败，不影响基本配置编辑。保存时保留后端返回但当前 UI 未展示的工具名称，只对 UI 管理的工具集合执行增删，避免无关字段被静默覆盖。

System Policy 清空使用空字符串表达明确清空；`null` 继续表示字段未提供。

### 依赖与锁文件

根 `requirements.txt` 增加 DOCX 嵌入 Excel 转换所需的核心依赖 `openpyxl`。使用当前 `package.json` 重新生成锁文件根元数据，使 Node engines 统一为 `>=22.19.0`。同时清理 `git diff --check` 报告的文件末尾空行。

## 错误处理

- workspace 授权请求不能用不存在、归档或非成员空间创建授权。
- RAG 请求不能使用失效成员关系或归档空间的旧授权。
- 关键配置加载失败时明确显示错误，不把失败伪装为空数据。
- 辅助列表加载失败时分别显示失败状态，避免误导为“暂无记录”。

## 测试

- API 集成测试覆盖非成员授权、归档空间授权、成员授权成功，以及移除成员后的 RAG 拒绝。
- 浏览器行为测试覆盖授权加载失败不会保存、未知工具保留、System Policy 可清空。
- 依赖/锁文件契约测试覆盖 `openpyxl` 和 Node engines 一致性。
- 最终运行全量 pytest、Ruff、JS 语法检查、两项 Playwright 验证和 `git diff --check`。
