# 子路径部署（lwa/Caddy 别名）可配置 base path 改造

## 背景与诊断（已实测）

部署地址 `http://10.180.106.12:8080/prd-review/` 经 `curl` 探测确认：
- lwa 底层是 Caddy（响应头 `Via: 1.1 Caddy`），用 `handle_path` 剥离 `/prd-review` 前缀转发到后端。
- `/prd-review/api/health`、`/prd-review/api/app/branding` 均 200 ✅，说明 Caddy 剥前缀 + 后端路由正常。
- **但 `/api/health`（根路径无前缀）也返回 200** —— 这意味着生产环境的前端打 `/api/...`（无前缀）是靠"根路径也被 Caddy 透传"歪打正着命中，而非真正走别名。换别名/多应用共享网关/收紧 Caddy 仅代理 `/prd-review/*` 时，前端数据层会全断。
- **生产部署的是旧版 `api.js`**（`_base: ''` 写死，无推导逻辑）——重新部署新版是前提。

源码新版 `api.js` 已设计好 `_base` 机制（优先 `window.__BASE_PATH__`，否则 currentScript 推导），但 **后端从未注入 `window.__BASE_PATH__`**，全仓 `__BASE_PATH__` 只有 `api.js` 读取、无人赋值。审计还发现 branding 资产 URL 是唯一未走前缀拼接的漏网。

> 严格遵守你的分层要求：**后端路由不动**（`/api/...`、`/assets/...` 保持原样，Caddy 负责剥前缀），**前端 API 不写死绝对地址**，改的是"让前端显式拿到可配置 base"。

## 改造内容（4 处代码 + 文档）

### 1. 后端注入 base path（核心）— `src/main.py`
- 新增 `@app.get("/")` 路由，**注册在 `app.mount("/", StaticFiles(...))` 之前**（Starlette 按注册顺序匹配，显式路由优先于 mount；现有所有 `@app.get` 已在 mount 前，安全）。
- 该路由读取 `src/static/index.html` 文本，把 `</head>` 替换为 `<script>window.__BASE_PATH__='<ROOT_PATH>'</script></head>`，用 `HTMLResponse` 返回（项目首次引入 `HTMLResponse`，模式参照已有 `serve_branding_asset` 的 FileResponse）。
- `ROOT_PATH` 已在 `main.py:89` 算好（`os.environ.get("ROOT_PATH","").rstrip("/")`），直接复用。
- **把注入逻辑抽成纯函数** `def _render_index(root_path: str) -> str`，便于测试；并对返回 HTML 加 `no-cache` 头（避免注入脚本更新后被浏览器旧缓存命中）。
- **无需 SPA fallback**：探查确认前端无 `history.pushState`/`popstate`/hash 路由，单入口应用，只处理根入口 `GET /` 即可。

### 2. 前端 branding 资产 URL 补前缀（修漏网）— `src/static/js/auth.js`
- `auth.js:225`（logo `<img src>`）：赋值时统一走 `API._url('/' + url)`，补上前缀。
- `auth.js:166`（favicon `<link href>`）：同上。
- 后端 `get_branding` 仍返回纯相对标识 `assets/branding/xxx`（不改），前缀在前端统一拼——保持"后端不耦合部署位置"的分层。

### 3. 前端 SSE 手拼 base 统一为 `_url`（风格统一，顺手）— `src/static/js/api.js`
- `api.js:383`（`getReviewProgress` 的 EventSource）：把手拼的 `` `${this._base}/api/review/...` `` 改为 `this._url('/api/review/...')`，与全局规范一致，避免日后 `_url` 增强逻辑时遗漏。
- `api.js:6-19` 的 `_base` 推导 fallback **保留不动**（currentScript 推导作为兜底无害，主路径仍是后端注入）。

### 4. 配置与文档 — `.env.example` + 部署说明
- `.env.example` 已有 `ROOT_PATH` 注释（保留），补充一句：lwa/Caddy 别名下需让代理同时覆盖 `/prd-review/api/*` 与 `/prd-review/assets/*`，**不要只透传根路径**（点明当前生产环境靠根路径透传兜底的脆弱性）。
- 更新 README 部署章节（若有）说明 base path 配置点。

## 不改的部分（明确边界）
- 后端所有路由 `/api/...`、`/assets/...` —— 保持不变，Caddy 负责剥前缀。
- skills、`AGENT_API_BASE`、另一个项目（home-bookshelf）—— 本次不动（按你选的范围）。
- `start.sh` 的 `--root-path` 逻辑 —— 已就绪，不动。

## 验证方式
1. **本地**：`ROOT_PATH=/prd-review start.sh`，`curl http://127.0.0.1:17957/` 断言返回 HTML 含 `window.__BASE_PATH__='/prd-review'`；用 FastAPI TestClient 对 `_render_index('/prd-review')` 写单测（纯函数，断言注入正确、空值时不注入多余内容）。
2. **部署后**：在 `http://10.180.106.12:8080/prd-review/` 打开浏览器，DevTools Network 确认所有 `/api/` 请求实际发往 `/prd-review/api/...`（带前缀）、登录页 logo/favicon 指向 `/prd-review/assets/branding/...`、SSE 通知流正常；并临时收紧 Caddy 只代理 `/prd-review/*` 验证不再依赖根路径兜底。
3. **回归**：`ROOT_PATH` 留空（根路径部署）时行为与改造前一致（`__BASE_PATH__=''`，`_url` 拼出无前缀路径）。
