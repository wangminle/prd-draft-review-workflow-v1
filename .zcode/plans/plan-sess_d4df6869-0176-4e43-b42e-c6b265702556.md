## 三、新建使用说明文档(8 篇,均双语)

每篇按"面向谁、解决什么、怎么操作"组织,内容基于代码实证(端点、配置项、角色、模式)。章节大纲:

### 1. `getting-started.md` — 快速开始
面向首次使用者。环境要求(Python 3.10+)、克隆、虚拟环境、装依赖、复制 .env.example→.env、生成 JWT_SECRET、填至少一个 LLM Key、`./start.sh`、访问 http://localhost:17957、首次 admin 登录、上传第一份 DOCX 跑 quick 模式验证。给出最小可运行配置。

### 2. `configuration.md` — 配置说明
基于 `.env.example` + `src/config.yaml` + `runtime/config/ui-branding.yaml` 实证。三类配置全覆盖:
- **环境变量(.env)**:LLM Keys、OPENAI_API_BASE、Embedding(EMBEDDING_MODEL/DIMENSIONS)、JWT_SECRET(必填校验规则)、ADMIN_INITIAL_PASSWORD、SERVER_PORT/HOST、ROOT_PATH(子路径反代)、RUNTIME_ROOT、CONFIG_PATH、AGENT_API_BASE
- **应用配置(config.yaml)**:server/database/auth(含 allow_public_registration、sse_ticket_ttl、token 有效期 480min)/models/upload/defaults/review(retry/pipeline/llm/upload 参数)
- **品牌配置(ui-branding.yaml)**:优先级(runtime > config.yaml > 代码默认)、各字段、资产目录 runtime/assets/branding/、路径安全约束
- 配置优先级总览、敏感项标注

### 3. `user-guide.md` — 用户使用手册
面向普通用户的全功能操作手册:
- **需求评审工作流**(核心):项目化组织 → 上传 DOCX → 选文档 → 选模式 → 运行 → 看报告。详述 6 种模式(quick/review/pm/insight/full/draft)各自回答的问题、触发技能、耗时(120-600s)、适用场景、递进关系与缓存复用
- **评审结果消费**:逐篇分析(6 维度)、体系评审(7 维度)、演进洞察、缺口分析、报告/PRD 草稿
- **知识库**:团队空间上传/检索、个人空间(Team/Mine 切换)
- **Agent 对话**:发起、@文档注入上下文、查看运行历史
- **账号**:改密码

### 4. `collaboration-review.md` — 协作评审
独立成篇(流程复杂)。ReviewRequest/Round/Participant 模型驱动的"汇报准备→材料确认→协作评审"流程:
- 创建协作评审请求(必填审批人)、多轮审批(pending_approval→决定)、Reviewer/Approver/Observer 角色与读写权限、重新提交
- Artifact 生命周期(draft→confirm 冻结→unconfirm)、对象级访问(BOLA 防护、Observer 只读)
- 评论与 @mention、resolve
- 实时通知(SSE + 铃铛 Inbox、批量已读/归档)

### 5. `admin-guide.md` — 管理员手册
基于 admin/governance/agent/pi_agent 路由。管理后台全功能:
- **用户管理**:创建/禁用/删除 user/admin、ADMIN_INITIAL_PASSWORD、注册策略(allow_public_registration、首 admin 离线初始化)
- **模型管理**:增删改、排序、启停、测试连接、测速、配置加密 API Key、thinking 设置
- **Prompt 管理**:通用/评审 Prompt
- **Skill 管理**:启停、回归测试、元数据
- **治理运营**:成本统计(日/周/自定义,按 workspace/user/mode 聚合)、质量统计(周聚合趋势)、Agent 归档退役、权限审计日志、Workspace 预算设置与告警(BudgetGuard 硬限)
- **Agent 管理**:身份/系统策略/授权范围/可用工具、运行历史、待审批工具调用、MCP 外部服务策略
- **品牌**:模板导出与配置指引
- 系统统计与最近访问

### 6. `api-reference.md` — API 参考
面向集成方。15 个路由组端点汇总表(auth/chat/history/upload/admin/review/workspace/agent/pi_agent/review_request/artifact/notification/governance):
- 认证方式(Bearer JWT, SSE 用短票据 sse-ticket, TTL 60s)
- 每组列出方法+路径+用途+鉴权要求
- 请求/响应要点(不逐字段展开,引用代码模型)
- SSE 流式端点说明

### 7. `security.md` — 安全与权限
面向安全审查/运维。基于代码实证的权限与安全模型:
- **角色体系**:系统级(user/admin)、工作空间级(owner/admin/member/viewer)、协作评审(Observer/Reviewer/Approver/发起人/项目管理员)
- **认证**:JWT + bcrypt、token 480min、SSE 短票据不走 query
- **访问控制**:对象级访问(object_access)、BOLA 防护、workspace 成员校验(require_action + is_active_member)、只读角色防篡改
- **Agent 安全**:deny-by-default 工具白名单(空→仅 rag_search)、高风险工具(bash/write/edit/read)需管理员配置+独立审批人、cwd 沙箱、MCP 鉴权
- **数据安全**:数据与代码分离(runtime git-ignored)、内网闭环、敏感项隔离(.env/品牌不进包)
- **上传安全**:file_id 路径穿越防护、扩展名/大小限制

### 8. `troubleshooting.md` — 常见问题
FAQ 形式。启动失败(JWT_SECRET 空/过短/占位值被拒)、模型连接失败/超时、端口占用、子路径反代 404、Agent 工具被拒、向量化卡住、SQLite 文件锁、数据迁移、版本更新回滚失败等。每条:现象→原因→解决。
