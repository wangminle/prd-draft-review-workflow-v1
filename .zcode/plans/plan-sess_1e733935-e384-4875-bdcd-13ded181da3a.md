## BUG-119（P0）：Agent 授权范围未真正生效

**根因**：Bridge 注入 `AGENT_SCOPE_JSON`，但 `agent-limiter.ts` 从不读取它；空白名单（`AGENT_ALLOWED_TOOLS=""`）时 `ALLOWED_TOOLS.length === 0` 跳过白名单检查，等于放行全部工具。

**改动 1 — `src/agent/extensions/agent-limiter.ts`**（Extension 层 fail-closed + 范围强制）：
- 读取并解析 `AGENT_SCOPE_JSON`（`default_scope_type` + `authorizations[].scope_type/scope_id/permissions`）。
- 白名单 **fail-closed**：未配置 `AGENT_ALLOWED_TOOLS` 时，默认只允许 `rag_search`（而非全部）；用 `_DEFAULT_ALLOWED` 覆盖空数组语义。
- 新增 `assertScope(toolName, input)`：对 `read/grep/find/ls`（只读文件类）解析 `event.input.path`（Pi `tool_call` 事件提供 `input.path`），按 `default_scope_type` 校验路径前缀——`personal` 仅允许 Agent 工作目录内文件，`workspace` 允许该 workspace 数据目录；越界 `block:true`。
- 在 `tool_call` handler 中调用 `assertScope`。
- 同步更新 `test_bug113_extension_source_reads_whitelist_env` 断言（新增 `AGENT_SCOPE_JSON` 读取断言），避免回归。

**改动 2 — `src/app/services/pi_agent_bridge.py`**：`_build_extension_env` 确保 `AGENT_SCOPE_JSON` 非空（profile 无 authorization 时给出 `{"default_scope_type":"personal","authorizations":[]}` 兜底，而非空），保证 Extension 的 fail-closed 总有可解析范围。

**验证**：新增 `test_bug119_*` — Extension 静态源包含 `AGENT_SCOPE_JSON` 读取；空 `AGENT_ALLOWED_TOOLS` 时默认仅 `rag_search`；非管理员 profile 白名单已 strip 高风险工具（既有逻辑，补断言）。

## BUG-120（P0）：聊天附件 file_id 目录穿越

**根因**：`ChatFileStorage.read_text()/delete()/file_exists()` 直接 `os.path.join(upload_dir, file_id)`，用户 `file_id="../../secret.md"` 可逃逸上传目录。

**改动 — `src/app/storage/chat_file_storage.py`**：新增私有方法 `_safe_join(file_id)`，做三层校验：
1. 拒绝非服务端生成的格式：`file_id` 必须匹配 `^[a-f0-9]+\.[a-z0-9]+$`（`save_upload` 用 `uuid4().hex + ext` 生成），含路径分隔符/`..` 直接 `ValueError → return None/False`。
2. `os.path.realpath` 后用 `os.path.commonpath` 校验结果路径仍是 `_resolve_upload_dir()` 的子目录。
3. `read_text/delete/file_exists` 全部走 `_safe_join`。

**验证**：新增 `test_bug120_*` — `read_text("../../etc/passwd")` / `read_text("../secret.md")` 返回 `None`；合法 `file_id` 仍可读；`save_upload` 生成的 id 通过校验。

## BUG-121（P0）：Workspace 配额在真实调用链中基本无效

两个独立缺陷，一并修复：

**缺陷 A — LLM 日志缺 workspace/user/mode 归属，聚合恒写全局行**：
- `src/app/logging_config.py`：`log_llm_session(...)` 新增可选参数 `workspace_id`、`user_id`、`mode`，写入 JSONL 条目。
- `src/app/services/cost_stats_service.py`：`aggregate_daily` 读取 entry 的 `workspace_id/user_id/mode`（缺失时 `mode` 仍由 `infer_mode_from_model` 兜底），聚合 key 用真实归属写入对应行。
- 两个调用点补传归属：
  - `src/app/routers/chat.py`（流式 finish）：传 `workspace_id=ws_id, user_id=user.id, mode="chat"`。
  - `src/app/services/retry.py`（`retryable_chat`，被 review pipeline/agent 复用）：`log_llm_session` 签名透传——`retryable_chat/structured_chat` 增加可选 `workspace_id/user_id/mode`，在成功/失败两条 `log_llm_session` 调用处传入；review pipeline（`_run_pipeline`）与 agent 调用处按其 workspace 传入（review 有 project→workspace，agent 用 default ws）。

**缺陷 B — 客户端可传不存在的 `knowledge_workspace_id` 选无配额空间**：
- `src/app/routers/chat.py`：在 `ensure_workspace_llm_allowed` 前校验 `req.knowledge_workspace_id` 真实存在且当前用户是其成员（`WorkspaceRepository.get_by_id` + `get_member`，不存在或非成员 → 404/403）；为 None 时保持回退默认空间。

**验证**：新增 `test_bug121_*` — `log_llm_session` 带 workspace_id 后 JSONL 含字段；`aggregate_daily` 写出 workspace 专属行；非成员传不存在/他人 workspace 的 `knowledge_workspace_id` 被拒（4xx），配额仍按 default ws 计。

> 注意：review pipeline 的 workspace 归属需要 project→workspace 映射，已有 `ReviewProject.workspace_id`（`_ensure_default_workspace` 保证非空）。agent 路径用 default ws（与现有 budget guard 一致）。

## BUG-122（P1）：SQLite 外键约束未开启

**根因**：`create_async_engine` 未注册 connect event 执行 `PRAGMA foreign_keys=ON`；实测 `PRAGMA foreign_keys=0`。

**改动 — `src/app/database.py`**：
- 用 SQLAlchemy event API（`from sqlalchemy import event`）对 `engine.sync_engine` 注册 `connect` 监听，每条连接执行 `PRAGMA foreign_keys=ON`。
- 新增幂等迁移 `_migrate_enable_foreign_keys_safety(conn)`：`init_db` 中 `create_all` 后执行一次孤儿清理（针对关键 `ON DELETE CASCADE/SET NULL` 关系，如 `ReviewParticipant`→`ReviewRequest`、`AgentRun`→`AgentProfile`、`Artifact`→`ReviewRequest`），删除引用不存在的行，避免开启 FK 后旧库启动失败。

**验证**：新增 `test_bug122_*` — 连接级 `PRAGMA foreign_keys` 返回 1；插入指向不存在父 ID 的行被拒绝（`IntegrityError`）；孤儿清理幂等（二次启动不报错）。保持现有测试 teardown `engine.dispose()` 不受影响。

## BUG-123（P1）：协作审查产物写权限退化为读权限

**根因**：`artifact.py` 的 `update_artifact_content/confirm_artifact/unconfirm_artifact` 只调 `assert_artifact_access()`（只读语义），Observer 也能改/确认/解冻。

**改动 — 权限矩阵**：Observer 只读；Initiator/Reviewer/Approver 及项目管理员/owner/admin 可写/确认/解冻。
- `src/app/services/object_access.py`：新增 `assert_artifact_write_access(db, artifact, user_id)`：
  1. `artifact.object_type == "review_request"`：查 `ReviewParticipant.get_by_request_and_user`，active 且 `role != "Observer"` → 放行；无参与记录 → 回退 `assert_project_access(..., action="write")`（owner/admin/member）。
  2. `object_type == "conversation"`：会话所有者放行（既有 `assert_conversation_access` 已校验归属）。
- `src/app/routers/artifact.py`：`update_artifact_content`/`confirm_artifact`/`unconfirm_artifact` 三处把 `assert_artifact_access` 换成 `assert_artifact_write_access`；`get_artifact`/`list_artifacts` 保持只读校验不变。

**验证**：新增 `test_bug123_*` — Observer 403（confirm/update/unconfirm 三动作）；Approver/Initiator 200；非参与者但项目管理员 200；只读 GET 不受影响。

## BUG-124（P2）：审查后台任务未纳入应用生命周期

**根因**：`review.py:882` 用裸 `asyncio.create_task(_run_pipeline(...))` 不存句柄；`lifespan` shutdown 直接 `engine.dispose()`，任务可能在引擎释放后仍在跑，产生 `aiosqlite: Event loop is closed`。

**改动 — 建立任务注册表 + 优雅停机**：
- `src/app/routers/review.py`：新增模块级 `_pipeline_tasks: dict[int, asyncio.Task] = {}`；`asyncio.create_task(...)` 改为 `task_obj = asyncio.create_task(...)` 并 `_pipeline_tasks[task.id] = task_obj`；`_run_pipeline` 的 `finally` 里 `self`-无关地 `_pipeline_tasks.pop(task_id, None)`。新增模块函数 `acquire_pipeline_shutdown()`（停止接新任务）和 `await_pipelines(timeout)`（取消并等待存量任务）。
- `src/main.py`：`lifespan` finally 中，在 `stop_embedding_worker()` 之后、`engine.dispose()` 之前，调用 `await_pipelines(timeout=10)` 等待/取消运行中的审查任务。
- 现有 `_run_pipeline` 的 `try/except/finally` 结构不变，只是确保 `finally` pop 句柄。

**验证**：新增 `test_bug124_*` — 模拟一个长跑 `_run_pipeline`（monkeypatch SkillRunner 为 await sleep），`lifespan.__aexit__` 后无 `Event loop is closed`、任务被 cancel/await；既有 `test_bug118_lifespan_disposes_engine` 保持通过（在 `await_pipelines` 之后才 dispose）。
